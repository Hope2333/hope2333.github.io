# Push261026 — v2 2.1.4（OpenTUI 0.6.8 ABI 修復）+ v2 2.0.32

[GitHub Release](https://github.com/Hope2333/opencode-termux/releases/tag/Push261026) · [中文版](/zh_CN/wiki/opencode-termux/release/Push261026.md) · [English](/en/wiki/opencode-termux/release/Push261026.md) · [Español](/es/wiki/opencode-termux/release/Push261026.md) · [日本語](/ja/wiki/opencode-termux/release/Push261026.md) · [繁體中文](/zh_TW/wiki/opencode-termux/release/Push261026.md)

## 概覽

本批為 **native 家族**的 v2 兩個版本，各出 deb + pacman `.pkg.tar.xz`，共
**4 包 + SHA256SUMS.txt**。**2.0.32** 是 2.0 線末版（opentui 0.5.17）；
**2.1.4** 是 2.1 線首個 0.6.x 渲染器 ABI（opentui 0.6.8）。兩者屬**兩條 ABI
軌**，依需求選線；它們共用 `opencode` 套件名，安裝其一即取代另一。

**關鍵修復（commit `d7ddcb5`）**：2.1.4 首個建置把 0.5.x 世代的 bionic
`libopentui.so` 覆蓋進所有版本的執行時目錄，導致 TUI 初始化即報
`Symbol "ot_scene_set_hooks" not found`（`--version` 與 `serve` 正常）。已從
上游 `sst/OpenTUI v0.6.8` 原始碼重建（與上游 glibc 件逐符號比對，1829 個
匯出符號零缺失，`readelf -d` 無 `libc.so.6`），並讓建置依 `OPENTUI_VER`
選件：未知版本**硬失敗**，不再靜默回落到錯誤 ABI；FFI 符號門亦依 ABI 分表。

## 驗證

實機（Android 9 / kernel `3.18.140-mokee` / aarch64）：兩版本 `--version`
正確、`serve` 回應 HTTP 200、TUI 完整渲染（2.0.32 為 123,184 B；2.1.4 為
101,980 B，tmux 抓屏含 banner／輸入框／工作階段列表），存活超過 15 秒。
`make verify-artifact` PASS（seccomp 強化 + web UI 資產）；shell 測試 76 ok。

## 已知問題

- 本批僅 **native**；compressed（UPX）與 wrapper 未建置。**v1 仍為 1.19.3**：
  上游 1.19.4 仍釘 `effect 4.0.0-beta.83`，在 3.18 核心上啟動即 SIGSEGV，
  需先完成原始碼重建。
- 舊 v1（1.18.35 以上）與更早 v2 在舊核心的 TUI 問題仍存在，詳見
  [Push261016](/zh_TW/wiki/opencode-termux/release/Push261016.md)。**本批 2.0.32 與 2.1.4 已在 3.18.140
  實測 TUI 可用。**
- 與 `opencode1` 共存安裝時，舊包共用 seccomp shim 路徑，`dpkg` 仍需
  `--force-overwrite`；後續批次將消除。

安裝：`pacman -U ./opencode-2.1.4-1-aarch64.pkg.tar.xz` 或
`dpkg -i ./opencode_2.1.4_aarch64.deb`；驗證：
`sha256sum -c SHA256SUMS.txt`。
