# Push261104 — 終端修正與 wrapper 雙代補齊

[GitHub Release](https://github.com/Hope2333/opencode-termux/releases/tag/Push261104) · [中文版](/zh_CN/wiki/opencode-termux/release/Push261104.md) · [English](/en/wiki/opencode-termux/release/Push261104.md) · [Español](/es/wiki/opencode-termux/release/Push261104.md) · [日本語](/ja/wiki/opencode-termux/release/Push261104.md) · [繁體中文](/zh_TW/wiki/opencode-termux/release/Push261104.md)

## 概覽

兩類靜默失效的修正，加上兩代 wrapper 家族的全量補齊。

- **v2 native `2.2.5-2`** — PTY 修復
- **v1 native `1.19.4-2`** — TUI 輸入修復
- **v2 wrapper** `2.0.0`–`2.2.5`（43 版）
- **v1 wrapper** `1.18.30`–`1.19.5`（12 版）

**120 個資產**：4 個 native、110 個 wrapper（每版 deb + pacman）、2 份校驗清單。

## 兩個修復

`POST /api/pty` 恆返 `500 ERR_DLOPEN_FAILED`——內嵌的 `librust_pty` 是 glibc
構建，bionic 沒有 `libpthread.so.0`。musl + shim 試過並放棄（dlopen 可行，但
Bun 在 `POST /api/pty` 時 `SIGSEGV@0x0`）。改為針對 `aarch64-linux-android`
原生編譯 bun-pty 的 Rust crate。

v1 則是啟動器把 TUI 放在背景進程組，永遠拿不到終端前台權，raw 模式設不上
（按鍵要 Enter、探測回應被回顯成垃圾）。啟動器改前台執行，並加一條「第二個
ESC 之後全部丟棄」的守衛。

## 安裝

```bash
curl -fsSL https://hope2333.github.io/repo/install.sh | sh -s -- --install opencode

pacman -S opencode     # v2（或 opencode-wrapper）
pacman -S opencode1    # v1（與 v2 並存）
```

## 已知問題

- **v1 native `1.19.5` 已撤回**：復活後的二進位在 Android 9 與 16 都會於
  `0x40` 段錯。v1 `1.19.5` 的 **wrapper** 不受影響、可正常使用。
- 兩套 bun 基底（revive 與 compile）不可互換。
- Android 11+ 覆蓋有限。
