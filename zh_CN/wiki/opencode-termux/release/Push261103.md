# Push261103 — v2 2.0.32 → 2.2.5 与 v1 1.18.33 → 1.19.4

[GitHub Release](https://github.com/Hope2333/opencode-termux/releases/tag/Push261103) · [中文版](/zh_CN/wiki/opencode-termux/release/Push261103.md) · [English](/en/wiki/opencode-termux/release/Push261103.md) · [Español](/es/wiki/opencode-termux/release/Push261103.md) · [日本語](/ja/wiki/opencode-termux/release/Push261103.md) · [繁體中文](/zh_TW/wiki/opencode-termux/release/Push261103.md)

## 概览

本批次把缺口一次补齐：不再只发最新版，而是把两代**全部已验收版本**一起放出。

- **v2 native** — `2.0.32`、`2.1.0`–`2.1.4`、`2.2.0`–`2.2.5`（12 版）
- **v1 native** — `1.18.33`–`1.18.35`、`1.19.0`–`1.19.4`（8 版）

每版都是 **deb + pacman**（`.pkg.tar.xz`）双格式：**40 个包 + SHA256SUMS.txt**。
全部为零 glibc 的 Android 原生二进制：上游源码用 android-bun 编译，TUI 走从源码
重建的 bionic `libopentui.so`——没有 wrapper、没有 proot、不依赖 musl。

不同版本会互相替换，请选定一条线。

## 本批次打通的构建问题

- **vite 8 原生绑定被剪**：`bun install --os=linux` 会重解析整棵树并剪掉
  android-only 的 optional 依赖（`rolldown`、`lightningcss`、`@tailwindcss/oxide`），
  随后 web UI 构建报 `Cannot find native binding`。现在按 `bun.lock` 里
  `{os:android,cpu:arm64}` 的条目直接取 tarball 补回。
- **平台包安装方式**：单包改为直接从 registry 取，不再为每个包跑一次完整的
  `bun install`（此前每次卡在 10 分钟超时上）。
- **PTY 包改名**：上游把 `@opencode-ai/pty` 改名成 `@opencode/pty`（2.2.2 删除、
  2.2.3 以新名回归）。包名现在由版本矩阵解析，不再硬编码。
- **opentui 0.8.0 补丁锚点**：原生资产目标挪进 `getCurrentNodeAssetTarget()`，
  上游已写死 `platform: "linux"`；补丁步骤改为校验这一性质，而不是在旧锚点上报错。

## 验收

本批每一版都在参考机（Android 9 / kernel `3.18.140-mokee` / aarch64）过同一组判据：

`安装 → --version → serve HTTP 200 → TUI 帧 → 键入回显 → 15 秒存活 → 无崩溃/降级标记`

`2.2.0`–`2.2.5` 于 2026-11-03 为本批次复验；其余版本在其构建轮次已于同机验收。
每个包另过 `make verify-artifact`（运行时二进制含 seccomp shim、v2 含内嵌 web UI），
上传后的 digest 与 `SHA256SUMS.txt` 逐条一致。

## 已知问题

- **v2 与 `opencode1` 并存安装**时，共享的 seccomp shim 路径可能仍需
  `dpkg --force-overwrite`。
- `2.2.5` 首屏会显示 `8 plugins failed`——插件兼容告警，不是崩溃，TUI、`serve`
  与键入均不受影响。
- 本批只发 **native** 家族；compressed（UPX）与 wrapper 不在其中。

安装：`pacman -U ./opencode-2.2.5-1-aarch64.pkg.tar.xz` 或
`dpkg -i ./opencode_2.2.5_aarch64.deb`；校验：`sha256sum -c SHA256SUMS.txt`。
