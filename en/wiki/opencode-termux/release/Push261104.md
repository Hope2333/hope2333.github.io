# Push261104 — Terminal fixes and full wrapper backfill

[GitHub Release](https://github.com/Hope2333/opencode-termux/releases/tag/Push261104) · [中文版](/zh_CN/wiki/opencode-termux/release/Push261104.md) · [English](/en/wiki/opencode-termux/release/Push261104.md) · [Español](/es/wiki/opencode-termux/release/Push261104.md) · [日本語](/ja/wiki/opencode-termux/release/Push261104.md) · [繁體中文](/zh_TW/wiki/opencode-termux/release/Push261104.md)

## Overview

Two silent-failure fixes plus a complete backfill of both wrapper families.

- **v2 native `2.2.5-2`** — PTY restored
- **v1 native `1.19.4-2`** — TUI input restored
- **v2 wrapper** `2.0.0`–`2.2.5` (43 versions)
- **v1 wrapper** `1.18.30`–`1.19.5` (12 versions)

**118 assets**: 4 native packages, 110 wrapper packages (deb + pacman per version), 2 checksum manifests.

## The two fixes

**v2 PTY.** `POST /api/pty` always returned `500 ERR_DLOPEN_FAILED` while TUI, `serve` and the web UI worked fine. The embedded `librust_pty` was a glibc build and bionic has no `libpthread.so.0`. The musl + shim route was tried and rejected — it dlopens, but Bun then hits `SIGSEGV@0x0` on `POST /api/pty`. The fix builds the bun-pty Rust crate natively for `aarch64-linux-android` (termios android cfg, static `libunwind.a`).

**v1 TUI.** The launcher ran the TUI in a background process group (to capture crash stderr), so it could never take the terminal foreground and never left canonical/echo mode — keys needed Enter and terminal probe replies were echoed back as junk. The launcher now runs in the foreground; a binary guard drops the second ESC so Termux's batched probe replies do not corrupt the stream.

## Notes

- Verified on Android 9 / kernel 3.18.140 and Android 16 / kernel 6.6.118.
