# Push261104 — Terminal fixes and full wrapper backfill

[GitHub Release](https://github.com/Hope2333/opencode-termux/releases/tag/Push261104) · [中文版](/zh_CN/wiki/opencode-termux/release/Push261104.md) · [English](/en/wiki/opencode-termux/release/Push261104.md) · [Español](/es/wiki/opencode-termux/release/Push261104.md) · [日本語](/ja/wiki/opencode-termux/release/Push261104.md) · [繁體中文](/zh_TW/wiki/opencode-termux/release/Push261104.md)

## Overview

Two functional fixes plus a full backfill of both wrapper families. Both fixes
are in the "everything looks green but the feature never works" class.

- **v2 native `2.2.5-2`** — PTY restored
- **v1 native `1.19.4-2`** — TUI input restored
- **v2 wrapper** `2.0.0`–`2.2.5` (43 versions)
- **v1 wrapper** `1.18.30`–`1.19.5` (12 versions)

**120 assets**: 4 native packages, 110 wrapper packages (deb + pacman per
version), 2 checksum manifests.

## The two fixes

**v2 PTY.** `POST /api/pty` always returned `500 ERR_DLOPEN_FAILED` while the
TUI, `serve` and the web UI worked. The embedded `librust_pty` was a glibc build
and bionic has no `libpthread.so.0`. The musl + shim route was tried and
rejected: it dlopens, but Bun then takes `SIGSEGV@0x0` inside `POST /api/pty`.
The fix compiles the bun-pty Rust crate natively for `aarch64-linux-android`.

**v1 TUI.** The launcher ran the TUI in a background process group (to capture
crash stderr), so it never held the terminal foreground and never left
canonical/echo mode — keys needed Enter and terminal probe replies were echoed
back as junk. The launcher now runs in the foreground; a binary guard drops
everything after a second ESC so batched probe replies cannot corrupt the input.

## Wrapper backfill

Both families are continuous now: v2 `2.0.0`–`2.2.5`, v1 `1.18.30`–`1.19.5`.
Two pipeline defects were fixed: `family-v2-wrapper` never fetched the glibc
tarball, and `wrapper-native` hardcoded an in-archive path that 2.0.19–2.0.22 do
not use.

## Install

```bash
curl -fsSL https://hope2333.github.io/repo/install.sh | sh -s -- --install opencode

pacman -S opencode     # v2 mainline (or opencode-wrapper)
pacman -S opencode1    # v1 mainline (coexists with v2)
```

## Known Issues

- **v1 native `1.19.5` is withdrawn.** The revived binary segfaults at `0x40` on
  both Android 9 and Android 16. The v1 `1.19.5` **wrapper** works and is
  available.
- **The two bun bases are not interchangeable** (revive vs compile).
- **Android 11+ coverage is limited**; full TUI judgement stays on Android 9.
