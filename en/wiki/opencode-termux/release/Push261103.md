# Push261103 — v2 2.0.32 → 2.2.5 and v1 1.18.33 → 1.19.4

[GitHub Release](https://github.com/Hope2333/opencode-termux/releases/tag/Push261103) · [中文版](/zh_CN/wiki/opencode-termux/release/Push261103.md) · [English](/en/wiki/opencode-termux/release/Push261103.md) · [Español](/es/wiki/opencode-termux/release/Push261103.md) · [日本語](/ja/wiki/opencode-termux/release/Push261103.md) · [繁體中文](/zh_TW/wiki/opencode-termux/release/Push261103.md)

## Summary

This batch closes the gap: it ships **every verified version** of both
generations instead of only the newest one.

- **v2 native** — `2.0.32`, `2.1.0`–`2.1.4`, `2.2.0`–`2.2.5` (12 versions)
- **v1 native** — `1.18.33`–`1.18.35`, `1.19.0`–`1.19.4` (8 versions)

Each version is built as **deb** and **pacman** (`.pkg.tar.xz`): **40 packages +
SHA256SUMS.txt**. All are zero-glibc Android binaries built from upstream source
with android-bun, rendering through a bionic `libopentui.so` rebuilt from
source — no wrapper, no proot, no musl.

runtime path. Inside v2, versions sharing the `opencode` name replace each
other — pick one line.

## Build fixes that unblocked this batch

- **vite 8 native bindings** — `bun install --os=linux` re-resolves the whole
  tree and prunes the android-only optional deps (`rolldown`, `lightningcss`,
  `@tailwindcss/oxide`), after which the web UI build dies with
  `Cannot find native binding`. The build now restores them by fetching the
  tarballs for the `{os:android,cpu:arm64}` entries recorded in `bun.lock`.
- **Platform packages** — single packages are fetched straight from the registry
  instead of re-running a full `bun install` per package, which previously
  burned 10-minute timeouts per attempt.
- **PTY package rename** — upstream renamed `@opencode-ai/pty` to
  `@opencode/pty` (dropped in 2.2.2, re-added in 2.2.3). The package name is now
  resolved from the version matrix instead of being hardcoded.
- **opentui 0.8.0 platform patch** — the asset target moved into
  `getCurrentNodeAssetTarget()`, which pins `platform: "linux"` upstream; the
  patch step now proves that property instead of failing on the old anchors.

## Verification

Every version in this batch passed the device criteria on the reference machine
(Android 9, kernel `3.18.140-mokee`, aarch64):

`install → --version → serve HTTP 200 → TUI frame → keystroke echo → 15 s
survival → no crash/degrade markers`

The `2.2.0`–`2.2.5` round was re-verified on 2026-11-03 for this batch; the
remaining versions were verified on the same device during their own build
rounds. Every package also passes `make verify-artifact` (seccomp shim present
in the runtime binary, web UI archive embedded for v2), and the uploaded
digests match `SHA256SUMS.txt` one by one.

## Known Issues

- **Co-installing v2 with `opencode1`** may still need
  `dpkg --force-overwrite` for the shared seccomp shim path.
- `2.2.5` shows `8 plugins failed` on first launch — plugin-compatibility
  warnings, not a crash; the TUI, `serve` and keystrokes are unaffected.
- Only the **native** family ships here; compressed (UPX) and wrapper are not
  part of this batch.

Install: `pacman -U ./opencode-2.2.5-1-aarch64.pkg.tar.xz` or
`dpkg -i ./opencode_2.2.5_aarch64.deb`; verify:
`sha256sum -c SHA256SUMS.txt`.
