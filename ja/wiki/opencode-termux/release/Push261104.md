# Push261104 — ターミナル修正と wrapper 全量補完

[GitHub Release](https://github.com/Hope2333/opencode-termux/releases/tag/Push261104) · [中文版](/zh_CN/wiki/opencode-termux/release/Push261104.md) · [English](/en/wiki/opencode-termux/release/Push261104.md) · [Español](/es/wiki/opencode-termux/release/Push261104.md) · [日本語](/ja/wiki/opencode-termux/release/Push261104.md) · [繁體中文](/zh_TW/wiki/opencode-termux/release/Push261104.md)

## 概要

静かに壊れていた 2 件の修正と、両世代 wrapper の全量補完です。

- **v2 native `2.2.5-2`** — PTY を修正
- **v1 native `1.19.4-2`** — TUI 入力を修正
- **v2 wrapper** `2.0.0`–`2.2.5`（43 版）
- **v1 wrapper** `1.18.30`–`1.19.5`（12 版）

**120 アセット**：native 4 件、wrapper 110 件（各版 deb + pacman）、
チェックサム 2 件。

## 2 つの修正

`POST /api/pty` が常に `500 ERR_DLOPEN_FAILED` を返していました。内蔵の
`librust_pty` が glibc ビルドで、bionic には `libpthread.so.0` がありません。
musl + shim は試したうえで断念（dlopen は通るが `SIGSEGV@0x0`）。bun-pty の
Rust クレートを `aarch64-linux-android` 向けにネイティブビルドする方式に変更。

v1 はランチャーが TUI をバックグラウンドのプロセスグループで起動していたため、
端末の前面権を取れず raw モードになりませんでした（キーに Enter が必要、
起動プローブの応答が文字化け）。ランチャーを前面実行に変更し、2 つ目の ESC
以降を捨てるガードを追加。

## 検証

| 環境 | 項目 | 結果 |
|---|---|---|
| Android 9 / 3.18.140 | `POST /api/pty` が実プロセスを返す | 合格 |
| Android 9 / 3.18.140 | serve / TUI / キー入力 / 15 秒 | 合格 |
| Android 16 / 6.6.118 | `--version`、`serve`、PTY の pid | 合格 |
| 全ビルド | wrapper の `--version` == 対象版 | 43/43 |

## インストール

```bash
curl -fsSL https://hope2333.github.io/repo/install.sh | sh -s -- --install opencode

pacman -S opencode     # v2（または opencode-wrapper）
pacman -S opencode1    # v1（v2 と共存）
```

## 既知の問題

- **v1 native `1.19.5` は撤回**：復元したバイナリが Android 9 / 16 の両方で
  `0x40` でセグメンテーション違反。v1 `1.19.5` の **wrapper** は利用可能。
- bun の 2 つのベース（revive 用 / compile 用）は互換ではありません。
- Android 11 以上の検証は限定的です。
